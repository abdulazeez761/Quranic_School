1

استنزاف الذاكرة وسحب التاريخ الكامل للطالب (Unbounded Memory Bloat)

خطورة حرجة | Memory & Performance
المشكلة الحالية تحت الضغط:

عند طلب سياق الطالب في GetStudentWirdContext، يتم استدعاء StudentRepository.GetByIdAsync الذي يقوم بعمل .Include(s => s.wirds) و .Include(s => s.Attendances).

إذا كان الطالب منتظماً منذ سنتين، يملك أكثر من 1,500 سطر من الأوراد والحضور، يتم تحميلها بالكامل في ذاكرة الـ RAM بواسطة EF Core Change Tracker فقط لمعرفة آخر سورة وآية!

المعالجة والحل الجذري:

الاعتماد على استعلام إسقاطي مباشر خفيف (Database Projection) بـ AsNoTracking و Take(1).

يقوم SQL Server بقراءة سطر واحد فقط من الجدول بالاعتماد على الفهرس بزمن أقل من 2ms دون سحب أي سجل حضور أو سجلات قديمة إلى الذاكرة.

2

تعدد اتصالات الداتابيس وغياب المعاملة الواحدة (5 Roundtrips per Save)

خطورة حرجة | Scalability & Atomicity
المشكلة الحالية تحت الضغط:

في WirdService.AddWirdAsync، يتم تنفيذ حلقة foreach تستدعي _context.SaveChangesAsync() لكل ورد على حدة (4 اتصالات منفصلة)، ثم استدعاء خامس لتحديث صفحات الطالب التراكمية.

في وقت الذروة (انتهاء الحصص وتسميع 20 حلقة متزامنة)، يسبب هذا استنزاف مجمع الاتصالات (Connection Pool Exhaustion) وبطء الاستجابة، مع خطر تكسر تناسق البيانات إذا انقطع الاتصال في منتصف العملية.

المعالجة والحل الجذري:

تجميع إضافة كل أوراد الطالب الأربعة وتحديث صفحات الطالب التراكمية في استدعاء واحد فقط لـ SaveChangesAsync() ومحاطة بـ BeginTransactionAsync().

تختزل العملية من 5 رحلات ذهاب وإياب إلى رحلة واحدة فقط تضمن نجاح الكل أو التراجع عن الكل (All-or-Nothing Atomicity).

3

تزاحم الواجهة الأمامية والنقر المزدوج (Double-Submit Race Condition)

خطورة عالية | UI/UX & Data Integrity
المشكلة الحالية تحت الضغط:

في دالة saveAndNextStudent()، لا يتم انتظار الحفظ (Missing await)، كما لا توجد حالة قفل أو تعطيل (Disabled) على زر "حفظ والتالي".

إذا واجه المعلم شبكة ضعيفة ونقر نقراً مزدوجاً (Double Click)، يخرج طلبان متطابقان للسيرفر في نفس اللحظة، فيتم إدراج الورد مرتين للطالب عن غير قصد.

المعالجة والحل الجذري:

جعل الدالة async/await وقفل الأزرار فور الضغط مع عرض مؤشر دوران (Loading Spinner).

لا يُفتح قفل الأزرار ولا يتم الانتقال للطالب التالي إلا بعد استلام تأكيد الحفظ بنجاح (HTTP 200 OK) من السيرفر.

4

غياب الفهرس المركب على جدول الأوراد (Missing SQL Server Composite Index)

خطورة متوسطة | Database Indexing
المشكلة الحالية تحت الضغط:

استعلام جلب آخر ورد يعتمد على: WHERE StudentId = @id AND Type = @type ORDER BY AssignedDate DESC.

مع نمو النظام إلى أكثر من 100,000 سطر، غياب فهرس يجمع هذه الأعمدة الثلاثة يجبر محرك SQL على فحص مساحات واسعة من الفهرس (Index Scan) مما يرفع استهلاك الـ I/O.

المعالجة والحل الجذري:

إضافة فهرس مركب عبر EF Core Migration: (StudentId, Type, AssignedDate DESC).

يجعل الوصول لآخر ورد يتم بعملية Seek فورية بزمن استجابة ثابت مهما بلغ حجم قاعدة البيانات.

1. كود توحيد الحفظ في معاملة واحدة (Atomic Batch Save)

استبدال الحفظ المتفرق في حلقة التكرار بحفظ تجميعي ذري ينفذ SaveChangesAsync() واحدة ويوفر 80% من اتصالات الداتابيس:

WirdService.cs — AddWirdsBatchAtomicAsync C# / Entity Framework Core 
public async Task<(bool IsSuccess, string Message)> AddWirdsBatchAtomicAsync(AssignWirdsBatchDto dto)
{
    if (dto == null || dto.Wirds == null || !dto.Wirds.Any())
        return (false, "لا توجد أوراد مدخلة لحفظها.");

    // استخدام ExecutionStrategy لضمان استقرار الاتصال وإعادة المحاولة في حال انقطاع مؤقت
    var strategy = _context.Database.CreateExecutionStrategy();

    return await strategy.ExecuteAsync(async () =>
    {
        await using var transaction = await _context.Database.BeginTransactionAsync();
        try
        {
            var student = await _context.Students.FindAsync(dto.StudentId);
            if (student == null)
                return (false, "تعذر العثور على بيانات الطالب.");

            decimal totalMemDelta = 0;
            decimal totalRevDelta = 0;
            var assignedDate = dto.AssignedDate ?? DateTime.Now;

            foreach (var wird in dto.Wirds)
            {
                wird.StudentId = dto.StudentId;
                wird.ClassId = dto.ClassId;
                wird.AssignedDate = assignedDate;

                if (wird.Status != AssignmentStatus.notSet)
                {
                    wird.IsCompleted = true;
                    wird.IsUpcoming = false;
                }

                // إضافة الكائن لتعقب السياق دون إرسال استعلام الآن
                _context.WirdAssignments.Add(wird);

                var (memDelta, revDelta) = ProgressContribution(wird);
                totalMemDelta += memDelta;
                totalRevDelta += revDelta;
            }

            // تطبيق الـ Delta التراكمي على نفس سجل الطالب
            if (totalMemDelta != 0 || totalRevDelta != 0)
            {
                student.TotalMemorizedPages += totalMemDelta;
                student.TotalReviewedPages += totalRevDelta;
            }

            // تنفيذ جميع أسطر الأوراد وتحديث الطالب في استدعاء SQL واحد فقط!
            await _context.SaveChangesAsync();
            await transaction.CommitAsync();

            return (true, $"تم حفظ أوراد الطالب بنجاح!");
        }
        catch (Exception ex)
        {
            await transaction.RollbackAsync();
            _logger.LogError(ex, "خطأ أثناء حفظ أوراد الطالب {StudentId}", dto.StudentId);
            return (false, "حدث خطأ غير متوقع أثناء حفظ الأوراد.");
        }
    });
}

2. تأمين الواجهة وقفل الأزرار لمنع النقر المزدوج (UI Lock Guard)

منع تكرار الإرسال وجعل الانتقال للطالب التالي معتمداً على نجاح الحفظ الفعلي في السيرفر:

wirdDrawer.js — saveAndNextStudent JavaScript ES6+ 
async function saveAndNextStudent() {
  const nextBtn = document.getElementById('drawerSaveNextBtn');
  const saveBtn = document.getElementById('drawerSaveBtn');
  const prevBtn = document.getElementById('drawerPrevBtn');

  // حماية: منع أي نقر مزدوج إذا كانت هناك عملية جارية
  if (nextBtn?.disabled) return;

  // قفل الأزرار وعرض مؤشر التحميل
  if (nextBtn) {
    nextBtn.disabled = true;
    nextBtn.dataset.originalHtml = nextBtn.innerHTML;
    nextBtn.innerHTML = "<i class='bx bx-loader-alt bx-spin'></i> جاري الحفظ...";
  }
  if (saveBtn) saveBtn.disabled = true;
  if (prevBtn) prevBtn.disabled = true;

  try {
    let isSuccess = true;
    if (typeof saveDrawerWirds === 'function') {
      isSuccess = await saveDrawerWirds(false);
    }

    // لا ننتقل للطالب التالي إلا بعد عودة استجابة السيرفر بنجاح
    if (isSuccess) {
      if (window.selectedStudentIndex < window.classStudents.length - 1) {
        window.selectedStudentIndex++;
        loadStudentIntoDrawer(window.selectedStudentIndex);
        document.getElementById('drawerWirdsList')?.scrollTo({ top: 0, behavior: 'smooth' });
      } else {
        closeWirdDrawer();
        Swal.fire({
          icon: 'success',
          title: '🎉 اكتملت الحلقة بنجاح!',
          text: 'تم حفظ وتقييم أوراد جميع طلاب الحلقة بنجاح تام.',
          confirmButtonText: 'ممتاز',
          confirmButtonColor: '#059669'
        });
      }
    }
  } catch (err) {
    console.error('Save failed:', err);
    showDrawerToast('تعذر حفظ أوراد الطالب. يرجى التحقق والمحاولة مجدداً.', 'error');
  } finally {
    // فك قفل الأزرار وإعادة النص الأصلي
    if (nextBtn) {
      nextBtn.disabled = false;
      nextBtn.innerHTML = nextBtn.dataset.originalHtml || "حفظ والتالي <i class='bx bx-chevron-left'></i>";
    }
    if (saveBtn) saveBtn.disabled = false;
    if (prevBtn) prevBtn.disabled = window.selectedStudentIndex === 0;
  }
}

خارطة طريق الانتقال للإنتاج المستقر (Production Deployment Guide)

1

المرحلة 1: تحسين استعلام سياق الطالب في الـ Backend

في StudentController.GetStudentWirdContext، استبدال استدعاء GetStudentByIdAsync باستعلام مباشر على جدول الأوراد بـ Take(1) لكل نوع دون عمل Include لكل سجلات الحضور السابقة.

2

المرحلة 2: توحيد الدفعة في استدعاء SaveChangesAsync واحد

في WirdService.AddWirdAsync، إزالة _context.SaveChangesAsync() من داخل حلقة الـ foreach، ووضعها مرة واحدة في النهاية محاطة بـ Transaction لضمان الذرية وحماية مجمع اتصالات قاعدة البيانات.

3

المرحلة 3: تأمين أزرار الـ Drawer ضد النقر المزدوج

تحديث saveAndNextStudent() و saveDrawerWirds() لتشمل وضع disabled ومؤشر التحميل لمنع أي طلبات متكررة قبل انتهاء الطلب الحالي.

4

المرحلة 4: الفهرس المركب في قاعدة البيانات

إضافة فهرس على الأعمدة: (StudentId, Type, AssignedDate) لضمان ثبات زمن استرجاع آخر ورد عند أقل من 1ms للأبد.

قائمة الفحص المعماري قبل إطلاق الإنتاج (Production Sign-off)

  • إزالة كشط الـ HTML والـ DOM Scraping
    تم التخلص منها بالكامل؛ والبيانات تُمرر الآن ككائنات JSON نظيفة أو تُجلب عبر API.
  • إزالة الـ LocalStorage تماماً من نافذة الأوراد
    لا توجد مسودات عشوائية أو تضارب بين الأيام والحلقات، والاعتماد بالكامل على قاعدة البيانات.
  • فصل وظيفة الإسناد (Drawer) عن وظيفة التعديل (Edit Modal)
    نافذة التعديل تعمل بالـ Id وبحساب الفرق الصافي ولا تكرر الأوراد، والـ Drawer مخصص فقط لإسناد اليوم.
  • استعلام سياق الطالب الخفيف (Direct SQL Projection)
    موصى به للإنتاج: استبدال جلب تاريخ الطالب الكامل باستعلام Take(1) مباشر لآخر ورد لتوفير الذاكرة.
  • حفظ الدفعة بـ SaveChangesAsync واحدة ومعاملة ذرية
    موصى به للإنتاج: تقليص الاتصالات من 5 إلى 1 وحماية التناسق في أوقات الذروة.
  • حماية النقر المزدوج (Double-Submit UI Lock)
    موصى به للإنتاج: تفعيل قفل الأزرار وعرض مؤشر التحميل في الـ Drawer أثناء الحفظ.
